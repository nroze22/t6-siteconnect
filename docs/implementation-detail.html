2. Screen-by-Screen Detail

SiteConnect has 10 screens accessible via numbered keyboard shortcuts (1–0). Navigation uses a Zustand store with instant page switching.

2.1 Screening (Key: 1)

Purpose: Three-panel patient screening interface — the primary workflow screen.

Left Panel — Patient Rank List

  • Patients sorted by eligibility score (0–100), highest first
  • Status filters: All, Eligible, Potentially Eligible, Needs Review, Ineligible
  • Review status filters: Pending, Accepted, Rejected, Deferred
  • Search by MRN / patient ID
  • Keyboard navigation: Arrow keys move selection, Enter selects
  • Score bar with color coding: green (≥80), amber (50–79), red (<50)
  • Shows inclusion met/total, exclusion triggered/total, missing data count

Center Panel — Criteria Detail

  • Lists every inclusion and exclusion criterion for the active study
  • Each criterion shows: result (met / not_met / unknown / needs_review), evidence text, evidence source category, confidence percentage
  • Rule-based vs. AI-determined indicator per criterion
  • Collapsible reasoning section for AI-evaluated criteria
  • Override button: Opens modal for clinician to override any result with justification text, creating an audit entry

Right Panel — Source Data

  • Displays raw patient data: demographics, diagnoses (ICD-10), medications, lab results, vitals
  • Auto-highlighting: When a criterion is selected, the source data that supports or contradicts it is visually highlighted
  • Lab values show dates, units, and reference ranges
  • Medications show dose, frequency, and active/inactive status

Study Context Bar

  • Study selector dropdown (switch between active studies)
  • Shows NCT number, sponsor, phase, therapeutic area
  • Study detail modal: Full study metadata including competition metrics and key criteria

What's smart: The screening engine evaluates all criteria simultaneously, infers evidence sources automatically (mapping ICD-10 codes to diagnosis criteria, lab test names to lab range criteria), and handles both wide and long data formats from any EHR.

2.2 Import (Key: 2)

Purpose: Four-step wizard for importing patient data from CSV files.

Step 1 — File Selection

  • Drag-and-drop zone or file browser (native Tauri file dialog)
  • Demo file button for web-mode testing
  • Epic format auto-detection: Recognizes PAT_MRN_ID, CURRENT_ICD10_LIST, etc. and shows a blue banner confirming Epic Clarity format

Step 2 — Column Mapping

  • Displays all CSV columns with AI-suggested target field mappings
  • Confidence scoring: Each mapping has a 0–100% confidence score based on fuzzy matching against 150+ EMR column aliases
  • Sample data preview: first 4 unique values from each column
  • Manual override: dropdown to reassign any column
  • Supports Epic, Cerner, Athena, and generic CSV formats

Step 3 — Import Progress

  • Real-time progress bar with stage indicators
  • Stages: Parsing → Deduplicating → Inserting → Screening
  • Patient count: imported, updated, skipped, errors

Step 4 — Results

  • Summary card: total imported, duplicates merged, errors
  • Auto-navigates to screening page when complete
  • Audit entry created for every import

What's smart: The column mapper uses 150+ aliases covering Epic Clarity, Cerner Millennium, Athena, and generic formats. Similarity scoring uses normalized token overlap with substring containment fallback. Wide vs. long format auto-detection checks for duplicate patient IDs in sample rows.

2.3 Trials Intelligence (Key: 3)

Purpose: Research study discovery, financial modeling, and opportunity ranking.

Study Cards

  • 30+ curated clinical trials from research pack, each showing:
  • Phase badge, therapeutic area tag, NCT ID, study acronym

Expandable Financial Detail

  • Visit model: Screening, treatment, and follow-up visit counts with cadence and duration
  • Burden breakdown: Operational (0–100), Startup (0–100), Screening (0–100) with color-coded bars
  • Revenue drivers: Top 5 line items with quantity, unit cost, total (e.g., "Treatment Visits: 12 × $850 = $10,200")
  • Action buttons: Open Budget Wizard, Screen Subjects, Generate Pitch PDF, Open in ClinicalTrials.gov

Page-Level Features

  • Full-text search across title, sponsor, indication, NCT ID

  • Summary metrics bar: Total Net Opportunity, Eligible Subjects, Active Studies

What's smart: The financial engine models each study using its detected archetype (20+ types), mapping to visit structures, labor models, and procedure costs. Site fit scoring considers the site's patient population match, operational capability, and financial preferences. The adaptive ranking uses weighted factors from the site profile (value vs. complexity vs. therapeutic area).

3. Core Engines & Algorithms

3.1 Rust Screening Engine

The screening engine evaluates patients against study criteria using structured rules. It runs in the Rust backend for maximum performance and security.

Rule Types (9 total)

Rule TypeLogicEvidence Output
AgeRangeComputed age from DOB within min/max bounds"Patient age: 62 (range: [18, 80])"
GenderIsCase-insensitive exact match"Patient gender: Male"
HasDiagnosisICD-10 prefix match + active status filter"Found C34.1 (NSCLC, active)"
NoDiagnosisAbsence of ICD-10 prefix in active diagnoses"No active M06.x diagnosis found"
HasMedicationDrug name substring match (case-insensitive) + active"Found: pembrolizumab 200mg"
NoMedicationDrug NOT on active medication list"No active warfarin found"
LabValueRangeMost recent value within range, 90-day lookback"ANC: 4200 /uL (range: [1500, ∞])"
VitalRangeMost recent vital within min/max range"BP systolic: 128 (range: [90, 160])"
And / OrComposite: all pass / at least one passesCombined evidence from sub-rules

Score Computation

inclusion_ratio = inclusion_met / inclusion_total
missing_penalty = missing_data / (inclusion_total + missing_data)
score = (inclusion_ratio × 100 × (1 - missing_penalty × 0.3)).clamp(0, 100)

Status Classification

  • ELIGIBLE (score = 100): All inclusion met, no exclusions triggered, no missing data
  • POTENTIALLY_ELIGIBLE (score 70–99): Inclusion ratio ≥ 0.7, missing ≤ 2
  • NEEDS_REVIEW: Missing data > 3, requires human evaluation
  • INELIGIBLE (score ≤ 30): Any exclusion triggered OR inclusion ratio too low

3.2 Financial Modeling Engine

The financial engine provides three-tier financial intelligence for every study.

Tier Architecture

  1. Tier 1 (Card Level): Fast directional range + burden badges — shown on study cards
  2. Tier 2 (Detail Level): Full modeled estimate using archetype-based protocol structure
  3. Tier 3 (Budget Wizard): Interactive scenario builder with site-specific assumption overrides

Study Archetypes (20+)

  • Oncology: infusion, immunotherapy, oral-targeted, advanced
  • Cardiovascular: simple, moderate, complex outcomes
  • Neurology: short/medium/long-duration, cognitive
  • Autoimmune: biologic, single-dose
  • Primary care: metabolic, hypertension
  • Pain management
  • Gene/cell therapy
  • Rare disease
  • Observational/registry

Each archetype defines: revenue-per-patient range, default visit structure, labor mix (coordinator/PI/nurse %), visit cadence, duration, and burden profile.

Integer-Cent Precision

All monetary values are stored and computed as integer cents (e.g., 4_200_000 = $42,000.00). This eliminates floating-point currency errors that plague spreadsheet-based financial models.

5. Security & Audit Architecture

5.1 Encryption

  • Database: SQLCipher with AES-256-CBC encryption, PBKDF2 key derivation (256,000 iterations), 4096-byte cipher page size
  • Passphrase flow: First run creates encrypted DB with user passphrase; returning users unlock with same passphrase
  • WAL mode: Enabled for concurrent read performance
  • Connection pool: r2d2 with max 4 connections, PRAGMA key applied on each connection checkout

5.2 HMAC-Chained Audit Trail

checksum[n] = SHA-256(checksum[n-1] || timestamp || action || details)
genesis seed = "0000...0000" (64 hex zeros)
  • Every data mutation creates an audit entry: UUID, RFC3339 timestamp, action enum, details string, SHA-256 checksum
  • Chain verification: iterates all entries, recomputes checksums, detects any tampering
  • Actions tracked: DatabaseInitialized, DataImported, ScreeningExecuted, CriterionOverridden, DatabaseUnlocked
  • Export: full JSON dump with chain verification status

5.3 Data Isolation

  • Zero network PHI: No patient data transmitted to any server, API, or cloud service
  • Local LLM: BioMistral-7B runs entirely on-device via llama.cpp sidecar
  • No telemetry: No usage tracking, analytics, or phone-home capabilities
